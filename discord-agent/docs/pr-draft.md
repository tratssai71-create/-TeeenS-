# PR の説明(下書き。まだ GitHub には出していません)

## 概要
AIで作ったホームページ(HTML)を、STUDIOに移植する「AIの作業チーム」(Discord → ディレクター → デザイナー → Codex)を、実用の形まで育てた。公開は、これまでどおり、必ず人が #approve で承認する。

## できるようになったこと
- **作る**: `!build N`(仕様書から依頼文を作って、1セクションを制作)。見本の画像も、Codex に見せる。
- **検査する**: `!check N`(文字・大きさ・色・行間・字間・フォント、配置のずれ)/ `!progress`(全セクションの表)/ `!compare`(元とSTUDIOを左右に並べた画像と、見た目の近さ)。スマホ幅は、編集画面を切り替えると、自動で、スマホの仕様で検査する。
- **直す**: `!fix N`(検査の違いから、直す依頼文を作る)/ `!fix N 配置`。
- **自動のディレクター**: `!auto N` / `!auto N-M` / `!auto all`(作る → 検査 → 直す を、最大3回まで繰り返す。詰まったら、止めて、人に聞く)。
- **普通の言葉で頼める**: #designer-chat で、気軽な言い方で、頼める。会話は続く(`!new` でリセット)。
- **育つ**: Codex が作業中に見つけたコツを「📝 学び」として記録(`docs/lessons.md`、`!lessons`)。`!accept` で「これでよい」を記録して、検査から外せる。
- **見える**: 作業のあと、STUDIOの画面を、自動で貼る(`!shot`)。

## 計測(2026-11-25〜27、実機)
- 文字の変更(#command): Codex 50秒 → 25〜38秒(合計 37〜52秒)。
- LP(10セクション)の制作: 1セクション約2〜7分。文字は、全セクションで、仕様書と一致(検査)。
- 仕様書づくり: 別の3サイトで、13〜25秒。見えている文字の拾えた割合は、96〜100%。

## 主な変更
- `bot.js`: 会話モード(`chatTurn`)、`!build` `!fix` `!auto` `!check` `!progress` `!compare` `!shot` `!accept` `!lessons`、画像の受け渡し、利用上限の案内、作業の順番待ち、例外のときも失敗を返す。
- `checker.js`(新規): 検査・配置の検査・許容(accept)・依頼文づくり。
- `browser-guard.js`: 速い整備(タブを使い回す)、編集画面の先開き、画面の撮影、Bot側の保存確認。
- `orchestrator.js`: 計測のログ、利用上限、確認の質問、`state.json` の安全な保存。
- `scripts/`: `make-spec.js`(仕様書)/ `spec-coverage.js` / `compare-images.js` / `compose-compare.py` / `export-text-image.js`。
- `docs/`: 手順書(`studio-playbook.md`)、引き継ぎ(`HANDOFF.md`)、学びの記録。

- 実機: STUDIO「discord テスト」プロジェクトで、全セクションを制作・検査。公開は、していない。

## 注意・既知の制限
- 画像(ロゴ・写真)の差し替えは、人の作業。背景の飾り(線の図形)、輪郭だけの文字は、STUDIOの標準部品では作れず、画像または、薄いグレーの塗り文字で代用。
- スマホ表示は、検査の仕組みはあるが、制作は、これから。
- Codex の利用上限(ChatGPT)に、何度も当たる。再開の時刻は、Bot が案内する。
- Bot を再起動するときは、子のプロセス(`run.js designer` / `run.js director`)まで止める。
- セキュリティレビュー(2026-11-27): 高い確度の指摘は、なし。
