- ブラウザ操作は、必ず登録済みの Playwright の道具(playwright/browser_navigate、browser_snapshot、browser_click、browser_type など)を使う。cua_repl は使わない。
- ブラウザは、作業の開始前に、Botが整えてある(古いタブは閉じ済み、キャッシュ消去済み、STUDIOのプロジェクト一覧が、1タブだけ開いている)。まず browser_snapshot で、そのタブを確認する。新しいタブは開かない。編集画面は、**その一覧の、対象プロジェクトの行(またはカード)にある「デザインエディタ」を押して開く**。直接URLは使わない。編集画面(左にレイヤー、中央にサイト)が表示されるまで、最大30秒待つ。
- 2026-11-25の実機の記録: 左の「レイヤー」パネルには、名前の検索欄が**ない**。レイヤー名「メインコピー」も見つからなかった。レイヤー検索には頼らない。
- **文字の変更の手順(2026-11-25に、実機で成功した方法。この順で、迷わず進める)**: ① 一覧で、対象プロジェクトの「○○: デザインエディタ」のリンクを browser_click で押す(snapshot の ref を、target に渡す)。② 上部ツールバーの「コンテンツ編集モードに切り替える」ボタンを browser_click で押す。押すと、右側の「右パネル」(region)に、ページ内の文字ごとの入力欄(`p`、contenteditable)が並ぶ。③ browser_find({text:"いまの文字"}) で、**右パネルの中の** 段落(paragraph)の ref を見つける(キャンバス上の見出し h1 ではない)。④ その ref に、browser_type({target:ref, text:"新しい文字", element:"右パネルの入力欄"}) で入力する(中身を置き換える)。⑤ browser_evaluate で、入力欄を blur() して(`document.activeElement.blur()`)、`main h1` など対象の要素の innerText が、新しい文字になったかを読む。**キャンバス上の見出し(h1)は、contenteditable=false で、browser_click すると5秒でタイムアウトするので、触らない。** 1回の exec に、複数の操作をまとめる(②と③、④と⑤など)。
- 変更後は、変更後の文字が、画面(または右パネル)に出たことを、browser_find か browser_evaluate で確認する。スクリーンショットは、撮らなくてよい。
- 画面右上の黒い「公開」ボタンは、通常の編集作業では押さない。タスクの題が「本番公開」で、公開を承認済みと書かれている場合だけ押す。
- 想定外の画面(ログイン画面、確認ダイアログ、エラー)が出たら、推測で進めず、状況を報告して止まる。
- 依頼にない箇所は、変更しない。
- レイヤーの木を1つずつ展開して探さない。要素は、browser_evaluate か browser_find(text または regex を指定)で探す。
- 「あああ(サンプル)」のホーム最上部の見出しは、`main h1` で取れる(browser_evaluate で `() => document.querySelector('main h1')?.innerText`)。
- 同じ操作(snapshot、tabs、click)を、3回以上くり返しても進まないときは、やり方を変えるか、状況を報告して止まる。
- 保存の確認は、作業指示の「再読み込み」の項に従う(Botが確認する場合は、自分で再読み込みしない)。元に戻っていた・反映されていなかったときは、完了にせず、やり直す(2回まで)。
- 報告には、「再読み込み後に、○○と表示されていた」と、確認した内容をそのまま書く。確認できていないのに、変更できたと書かない。
- browser_navigate / browser_click が「Frame has been detached」「Target closed」などで失敗したら、同じ操作をくり返さない。次の順で回復する: ① browser_tabs で、タブ一覧を見る → ② browser_tabs の new(新しいタブ)で、新しいタブを開く → ③ その新しいタブで、**一覧(https://app.studio.design/projects)を開き、「デザインエディタ」を押して**編集画面を開く → ④ 古い、壊れたタブは、browser_tabs の close で閉じる。それでも開けなければ、状況を報告して止まる。
- 作業を始める前に、browser_tabs でタブ一覧を見て、編集に使うタブが1つだけになるように、不要なタブを閉じておく。
- 編集画面を開いた直後は、読み込みに10〜20秒かかり、一時的に画面が空白になる。空白や「404」のように見えても、すぐに失敗にしない。15秒待って、もう一度スナップショットを撮る。それでも空白なら、一覧から「デザインエディタ」で開き直す(直接URLの再読み込みはしない)。ログイン画面が出たら、ログインが切れているので、報告して止まる。

- プロジェクトIDやURLは、自分で書き写さない(文字の写し間違いで、アクセス権限エラーになった例がある)。必ず、一覧の画面にあるリンクや「デザインエディタ」ボタンを使う。
- 1回の編集作業は、5分以内を目安にする。操作が1つ5秒以上止まる(タイムアウトする)ときは、同じ操作をくり返さず、別の方法(レイヤー検索→右パネルで入力)に切り替える。
- **速く終わらせる型(2026-11-25 の計測: 1回の exec は、モデルの往復で約3秒かかる。往復の数が、そのまま時間になる)**: 全体で、exec は4〜5回以内にする。「ページパネル」「レイヤーパネル」は開かない(ホームの最上部の見出し = 編集画面を開いたとき最初に出るページの `main h1`)。1回の exec の中で、snapshot の文字から ref を正規表現で取り出して、続けて操作する。**作業指示に「編集画面は、Botが、いま開いている」と書いてあるときは、一覧から開く手順(下の例の最初の2行)を飛ばし、browser_wait_for で編集画面が出るのを待つだけにする。**書いていないときの例(道具を読み込んだあとの、2回目の exec):
```js
const ref = (s, re) => s.match(re)?.[1];
let s = (await tools.mcp__playwright__browser_snapshot({})).content[0].text;
await tools.mcp__playwright__browser_click({target: ref(s, /link "[^"]*デザインエディタ"[^\n]*\[ref=(e\d+)\]/)}); // 対象プロジェクトの行のリンクを選ぶこと(複数あるときは、プロジェクト名で絞る)
await tools.mcp__playwright__browser_wait_for({text: "コンテンツ編集モードに切り替える"});
s = (await tools.mcp__playwright__browser_snapshot({})).content[0].text;
await tools.mcp__playwright__browser_click({target: ref(s, /button "コンテンツ編集モードに切り替える"[^\n]*\[ref=(e\d+)\]/)});
s = (await tools.mcp__playwright__browser_snapshot({})).content[0].text;
text(s.split("\n").filter(l => /右パネル|paragraph \[ref=/.test(l)).slice(0, 40).join("\n")); // 右パネルの入力欄(paragraph)の一覧を見て、いまの文字と一致する ref を選ぶ
```
  次の exec で、browser_type({target: その ref, text: "新しい文字", element: "右パネルの入力欄"}) → browser_evaluate で blur() して、`main h1` の innerText を読む、までを1回にまとめる。

- **STUDIOでの制作ルール(2026-11-25、利用者の指定。新しい要素をつくるときに守る)**:
  - 「blank」(何もない空の要素・空のレイアウト)は、**なるべく使わない**。使うのは、ほかの標準の部品では、どうしても作れないときだけ。
  - 制作のときは、**STUDIOの標準装備(標準の部品・標準の機能)だけで、ほとんどを作る**。外部のコードや、特別な仕掛けに頼らない。
  - **リッチテキストは、必要でないときは使わない**。ふつうの文章は、標準のテキスト要素で作る。
  - **絶対位置(位置を数字で固定する配置)も、必要でないときは使わない**。並べる・間隔をあける、は、標準の縦横の並び(スタック)や余白で作る。
  - どうしてもルールを破る必要があるときは、**破る前に、理由を報告に書く**(勝手に、黙って破らない)。
