- ブラウザ操作は、必ず登録済みの Playwright の道具(playwright/browser_navigate、browser_snapshot、browser_click、browser_type など)を使う。cua_repl は使わない。
- ブラウザは、作業の開始前に、Botが整えてある(古いタブは閉じ済み、キャッシュ消去済み、STUDIOのプロジェクト一覧が、1タブだけ開いている)。まず browser_snapshot で、そのタブを確認する。新しいタブは開かない。編集画面は、**その一覧の、対象プロジェクトの行(またはカード)にある「デザインエディタ」を押して開く**。直接URLは使わない。編集画面(左にレイヤー、中央にサイト)が表示されるまで、最大30秒待つ。
- 画面の左に「レイヤー」パネルがある。名前の検索欄で、探したい要素(例: メインコピー、見出し)を検索して選ぶ。
- 文字の変更は、レイヤーを選ぶと右パネルに出る「テキスト」欄の文字を書き換える。キャンバス上の文字を直接ダブルクリックして編集してもよい。
- 変更後は、キャンバスの表示が変わったことを、スクリーンショット1枚で確認する。何度も撮り直さない。
- 画面右上の黒い「公開」ボタンは、通常の編集作業では押さない。タスクの題が「本番公開」で、公開を承認済みと書かれている場合だけ押す。
- 想定外の画面(ログイン画面、確認ダイアログ、エラー)が出たら、推測で進めず、状況を報告して止まる。
- 依頼にない箇所は、変更しない。
- レイヤーの木を1つずつ展開して探さない。レイヤーパネルの検索欄に名前を入力して絞り込む(または browser_find で探す)。クリックと確認のくり返しを、増やさない。
- 「あああ(サンプル)」のホーム最上部の見出しは、レイヤー名「メインコピー」(h1)。その下の説明文は「サブコピー」。
- 同じ操作(snapshot、tabs、click)を、3回以上くり返しても進まないときは、やり方を変えるか、状況を報告して止まる。
- 編集したら、**保存されたことを確認してから**完了にする。手順: 変更後に数秒待つ → ページを再読み込みする(browser_navigate で同じURLを開き直す) → 同じ箇所の文字を読み直して、変更後の内容になっているか確かめる。再読み込みしても元に戻っていたら、完了にせず、やり直す(2回まで)。
- 報告には、「再読み込み後に、○○と表示されていた」と、確認した内容をそのまま書く。確認できていないのに、変更できたと書かない。
- browser_navigate が「Frame has been detached」「Target closed」などで失敗したら、同じ操作をくり返さない。次の順で回復する: ① browser_tabs で、タブ一覧を見る → ② browser_tabs の new(新しいタブ)で、新しいタブを開く → ③ その新しいタブを選んで、編集画面のURLを browser_navigate で開く → ④ 古い、壊れたタブは、browser_tabs の close で閉じる。それでも開けなければ、状況を報告して止まる。
- 作業を始める前に、browser_tabs でタブ一覧を見て、編集に使うタブが1つだけになるように、不要なタブを閉じておく。
- 編集画面を開いた直後は、読み込みに10〜20秒かかり、一時的に画面が空白になる。空白や「404」のように見えても、すぐに失敗にしない。15秒待って、もう一度スナップショットを撮る。それでも空白なら、ページを1回だけ再読み込みして、もう15秒待つ。ログイン画面が出たら、ログインが切れているので、報告して止まる。
- 編集画面のURLを直接開いて、15秒待っても、白い画面や404になる場合は、一覧から開き直す。手順: browser_navigate で https://app.studio.design/projects を開く → 対象のプロジェクト名(例: 「あああ」)の行にある「デザインエディタ」を押す → 編集画面(左にレイヤー、中央にサイト)が表示されるまで待つ。この方法で開けるので、2回までやり直してよい。
